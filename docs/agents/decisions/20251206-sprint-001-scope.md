Summary
- Choose stabilization/quality sprint over new tool features for the next two weeks.

Decision
- Focus areas: localization parity, UX/a11y polish for existing tools, regression coverage (unit + Playwright), and admin auth enforcement checks.
- Deliverables: clean `npm run validate`, passing `npm run qa:translations`, updated smoke tests for base64/hash/markdown-to-pdf and admin CRUD, progress-state UX for large inputs.

Rationale
- Privacy-first promise needs strong client-side UX and localization correctness before expanding tools.
- Existing tests cover basics; targeted smokes reduce regressions during future feature work.

Out of scope
- Building new tools or major design rebrands.
- Server-side processing beyond existing fallbacks.

Risks/Mitigations
- Risk: translation churn; mitigation: lock keys with `qa:translations` gate and allowlist review.
- Risk: flaky e2e; mitigation: keep smokes minimal, run in CI with retries where supported.
